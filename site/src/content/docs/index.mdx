<Aside type="caution">
riff is young and built spec-first — every feature traces to a numbered spec in
[`specs/`](https://github.com/candril/riff/tree/main/specs). It talks to GitHub through the
[`gh` CLI](https://cli.github.com/) and it *writes*: comments, reviews, resolutions, PR bodies.
Point it at a PR you don't mind poking at, and expect rough edges.
</Aside>

```sh
git clone https://github.com/candril/riff.git && cd riff
bun install && bun run build   # → dist/riff
riff                           # review your uncommitted changes
```

![The README demo](../../assets/riff-demo.gif)

## One diff, four ways to name it

riff takes a target and works out what you meant. A PR number, a revset, a URL, or nothing at
all:

```sh
riff                    # uncommitted changes in the working copy
riff pr                 # the PR for the current branch or bookmark
riff 123                # PR #123 in this repo
riff HEAD~3             # the last three commits
riff main..feature      # a branch comparison
riff @-                 # a jj revset
riff gh:facebook/react#1234
```

Local and PR mode are the same app. Every motion, every fold, every comment key works in both —
PR mode just has GitHub on the other end of it.

## The diff reads like a buffer

![The diff with the file tree open](../../assets/screenshots/tree.png)

`j k h l`, `w b e`, `f t ; ,`, `0 ^ $`, `gg G`, `Ctrl+d`/`Ctrl+u` — the motions are the ones your
fingers already know. `]c`/`[c` steps hunks, `]f`/`[f` files, `]u`/`[u` the files you haven't
looked at yet. `za`/`zo`/`zc` fold a file or a hunk, `zR`/`zM` do the lot. `Ctrl+o`/`Ctrl+i` walk
a real jumplist, so every jump is undoable.

## Comment on the line, not on a web form

`c` opens the comment panel anchored to the cursor's line; `V` first if the comment is about a
range. `C` hands the draft to `$EDITOR` instead. Comments land in `.riff/` in your repo — they
are yours until you decide to publish, so half a review survives a closed terminal.

![A thread in the comments panel](../../assets/screenshots/thread.png)

`]r`/`[r` walks every thread in the diff, `Enter` opens the one under the cursor; `]R`/`[R` skips
the resolved ones. `gC` is a fuzzy picker over every comment in the PR.

## Publish deliberately

Nothing reaches GitHub until you say so. `gS` opens the review preview — approve, request changes,
or comment, with every pending comment batched into one review. `gs` syncs the smaller stuff:
edits to comments you already posted, replies to other people's threads, resolutions. `S` posts a
single comment immediately when it can't wait.

## Everything the keyboard can reach

<CardGrid>
  <Card title="PR overview" icon="document">
    `i` toggles between the diff and the PR: description, conversation, review threads, checks,
    approvals, commits, files. `l` expands a failing check into its annotations; `Enter` opens the
    offending line in `$EDITOR`.
  </Card>
  <Card title="Commit-by-commit" icon="seti:git">
    `]g`/`[g` filters the diff down to one commit at a time and wraps back to the full diff — the
    way you'd read a stacked PR without checking anything out.
  </Card>
  <Card title="Viewed tracking" icon="approve-check-circle">
    `v` marks a file viewed and jumps to the next unviewed one. In PR mode the state is GitHub's
    own viewed status, so it survives the session and matches the web UI.
  </Card>
  <Card title="Flash jump" icon="rocket">
    `s` dims the diff and searches what's on screen as you type; every match gets a one-key
    label, and pressing it puts the cursor there. Search and jump in one motion.
  </Card>
  <Card title="Search that behaves" icon="magnifier">
    `/` and `?` search the rendered diff, `n`/`N` repeat, `*`/`#` take the word under the cursor.
    Matches highlight in place; `Esc` clears them.
  </Card>
  <Card title="Action menu" icon="open-book">
    `Ctrl+p` lists every action available in the current state with its shortcut — the same list
    the docs are generated from. Nothing has to be memorised.
  </Card>
  <Card title="Drop into your editor" icon="pencil">
    `gf` opens the current file at the cursor's line in `$EDITOR`, `gF` in a new tmux window with
    riff still running, `gc` checks out the PR branch first.
  </Card>
  <Card title="Links people can follow" icon="external">
    `gY` copies a GitHub permalink for the selection, the line, or the file, pinned to the branch.
    `gy` copies the PR URL, `y` in the comments panel copies a link to that thread.
  </Card>
  <Card title="Claude Code, scoped" icon="star">
    Chat about the selection, a file, a folder, a multi-select, or the whole diff. A comment
    Claude drafts shows up as a notification you copy with `gd` or dismiss with `gD` — riff never
    posts it for you.
  </Card>
  <Card title="Quiet background sync" icon="setting">
    New replies arrive on a poll that costs one GraphQL point per tick, skipped while the terminal
    is unfocused and refreshed when you come back to it.
  </Card>
  <Card title="Noise stays hidden" icon="seti:config">
    Lock files, generated code and snapshots are folded out of the review by default, and the
    pattern list is yours to redefine.
  </Card>
  <Card title="git or jj" icon="seti:folder">
    Both are first-class. Revsets, bookmarks, `@-` — riff asks whichever tool the repo actually
    uses.
  </Card>
</CardGrid>
